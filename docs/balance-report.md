# 初始数值验证报告（balance-v0.1 历史基线）

本报告是 v0.1 历史结果，不能用于评价当前 v0.2 策略。最新统计见 [demo-review.md](demo-review.md)。

日期：2026-10-10。配置：`configs/balance-v0.1.json`。数据：`results/bot-matchups.json`（36 局）、`results/random-games.json`（100 局）。机器环境见 `scripts/benchmark.py` 输出（Python 3.13.5 / Windows 11 / Intel64，约 1279 tick/s 无界面推进）。

> 这些是调参目标的首轮检验，尚未证明最优策略平衡；固定脚本集的胜率不能证明最优策略平衡。所有结论限定在当前脚本能力下。

## 1. 四脚本两两对战并换边（六组 × 双边 × 3 seed = 36 局）

| 对局 | 结果（按策略累计） |
| --- | --- |
| node_grabber vs turtle | 抢点 6 : 0 防守 |
| node_grabber vs robot_push | 3 : 3（依赖种子/换边） |
| node_grabber vs tech_siege | 3 : 3 |
| turtle vs robot_push | 防守 6 : 0 机器人推进 |
| turtle vs tech_siege | 防守 6 : 0 科技攻城 |
| robot_push vs tech_siege | 0 : 6 科技攻城 |

- 胜负/平局：p0 16 / p1 20 / 平 0（换边后没有策略通吃；两组 3:3 说明种子探索有效）。
- 总部摧毁率 33%（12/36），超时率 67%。
- 平均模拟局长 170.9 秒，P95 = 180 秒（触及六轮上限）。
- 节点易主平均 3.2 次/局。
- 资源花费构成（双方合计）：生产 > 信号 > 轰炸 > 建筑 > 维修 > 科技。
- 兵种死亡合计：狗约 435、机器人约 123、攻城车约 51（狗是消耗品主力）。

**路线竞争力**：四条路线均有胜场（抢点克防守、防守克推进与攻城、攻城克推进；抢点对推进/攻城各为 3:3），满足"至少三条路线有竞争力"的首轮目标。

## 2. 随机合法对战 100 局（M4）

- 100/100 全部在六轮内结束（自然终局）；胜负 56:44，无平局。
- 总部摧毁率仅 2%，超时率 98%；平均局长 179.3 秒，节点易主平均 5.2 次。
- 随机轨迹覆盖不同动作序列（seed 驱动），满足"至少 100 局覆盖不同动作轨迹"。

## 3. 与调参目标的差距（待验证的假设）

1. **多数对局落在 90–180 秒**：达标但偏向 180 秒上限（脚本对战 2/3 超时）。若希望更多总部决胜，按规则 §9 优先调**总部 HP、攻城伤害与路程**（例如总部 500→400 或攻城对建筑 35→40），一次只改一组。
2. **龟缩是否占优**：防守脚本对推进/攻城全胜，但被抢点完克，且超时局靠节点分定胜负——不构成通吃；暂不调维修/节点积分，继续观察。
3. **抢点滚雪球**：抢点对防守 6:0 主要来自节点收入+积分；若后续样本继续一边倒，按 §9 先调**节点收入（20→10）**而非移除争点。
4. **脚本能力差距**：四脚本为固定优先级策略，未做微操优化；3:3 对局说明胜负对种子敏感，样本不足以支持更细的数值结论。
