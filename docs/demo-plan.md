# 《断链协议》四方 Demo 实施与后续计划

当前主版本 v0.5，详见 [游戏规则](game-rules.md) 与 [当前验收](base-review-v0.5.md)及[规则核对](rules-audit-v0.5.md)。旧回合制计划见 [demo-plan-v0.2.md](demo-plan-v0.2.md)。

## 已完成

1. 新框架：四方持续交战、同时提交动作、最后存活者胜、无经济积分。
2. 战术闭环：城墙/授权门、中继链路、无人机接力、信号弹、制导导弹、屏蔽云和固定干扰器。
3. 演示：科技风金属战场、四反应堆基地、真实飞弹/失锁/EMP、生命条、算法决策、四方状态、点击追踪、暂停/单步/倍速、导出回放。
4. 训练入口：41 离散动作、四方合法掩码、固定 2681 维观测、淘汰/自然终局标志和回放验证。
5. 测试：109 项回归、24 策略位置排列、12 随机合法四方对战（当前v0.5验证；历史v0.3曾跑100局）。

## 展示流程

打开页面自动运行四种算法：破墙突击、信标制导、电子战压制、堡垒反击。

先观察部队争夺中继及链路连线，再观察信号柱、导弹弹体与 EMP 云。点击单位解释在线/离线，以及正在执行的旧命令；点击城墙解释授权门、遮挡和破墙。进入 120 秒过载后，展示真实伤害、有限维修、阵营淘汰和最终存活者。

用单步检查导弹“锁定→失锁→低伤害落地”，或换阵容比较战术。观看者不承担军队操作。结算屏必须明确无资源评分，多个存活者在硬上限时无冠军。

## 下一阶段

- 平衡：制导脚本当前占优，军事/电子战进攻偏弱。先改脚本目标和推进逻辑，再按组评估壁垒 HP、破城效率、技能成本/冷却及维修；每次保存配置版本与结果。
- 把过载期前的核心战损、墙突破、中继失守与失锁频率纳入统计，避免仅看冠军数量。
- 扩大对手池与位置轮换，加入 RL 自博弈或对脚本学习；奖励和淘汰处理按四方环境设计。
- 如加入迷雾，拆分裁判与可见状态，定义侦察及导弹锁定条件，并升级 schema。
- 再制作正式选手接口、部署/比赛运行与分发；不在玩法未收敛时先搭完整赛事工程。

## 首要验收约束

任何改动不得让资源或占领累计直接决定冠军。信号/导弹/屏蔽/墙必须同时有规则作用、可见表现与对应测试；动画不能代替核心实现。

## 兵种可读性与无人机限制

已实现四兵种职责卡片、列表职责标签、地面模型尺寸增强和真实通信护卫行为。无人机无武装、不占点，每方最多2架；机甲/炮塔可跨墙防空。后续优先改善地面交战与电子战基线，避免主要靠末段过载结束比赛。

## 基地扩展 v0.5

已实现29×29地图、9×9基地及7×7内部空间，四种防御设施开局直接展示。迫击炮使用弧线与落点圈，防空塔使用独立高塔模型与激光；建筑加入可点击追踪列表。继续保持四个算法自动对战及180秒上限。下一阶段评估防御强度与攻城推进，减少过载阶段同时毁灭的平局。
