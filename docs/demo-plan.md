## 已完成

- 四方持续交战、算法同时决策，最后存活者获胜；资源不直接判胜。

- 机器狗抢点、机甲护卫/防空、破城机拆墙、无人机无武装通信接力；每方无人机上限2架。
- 磁轨炮、迫击炮、防空塔、干扰阵列各有作用；信号、制导导弹、EMP实现通信与反制。
- 3D模型、不同射击效果、生命条、职责说明、算法决策与实体追踪；支持暂停、单步、倍速和导出回放。
- 41个离散动作编号、2681维固定观测、合法掩码、淘汰奖励与历史回放验证；GitHub自动测试已接入。

## 演示流程

打开本地页面，四种脚本策略自动对战，观看者无需操作军队。

1. 观察机器狗争夺中继及无人机延伸链路。
2. 点击地面部队、城墙或防御建筑，查看职责、当前目标、生命和联网状态。
3. 用暂停/单步观察信号弹、导弹锁定、EMP失锁与落弹伤害。
4. 观察陆军破墙，以及迫击炮的地面范围打击、防空塔拦截无人机。
5. 120秒后进入过载，展示真实核心伤害、有限维修和最终淘汰；结算不使用资源评分。

## 下一阶段

先改善军事推进与电子战脚本，再调整防御强度、破城效率、技能与维修数值，降低过载阶段同时毁灭的平局。统计应同时关注过载前核心战损、墙突破、中继失守和导弹失锁。

之后扩大对手池与位置轮换，接入强化学习训练，再考虑自由建筑布局、迷雾、正式选手SDK与比赛部署。规则或观测改变时按 [版本管理流程](version-management.md) 留存旧配置和回放。

## 验收约束

任何改动不得让资源或占领累计直接决定冠军。信号、导弹、屏蔽、城墙与防御建筑必须同时有规则作用、可见表现和对应验证。
