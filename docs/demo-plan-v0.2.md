# THUAI10《算力领土》演示 Demo 实施计划

日期：2026-10-10。依据：[游戏规则 v0.2](game-rules.md) 与 [杨坤烨原始想法及取舍](idea-source.md)。本文件记录开发方向。当前核心、3D 自动观战和 RL 接口已实现；数值仍需验证。最新预期核对与修复见 [demo-review.md](demo-review.md)。

## 1. 演示目标

让成员在一次三分钟对局中看懂“建设选择 → 布局与维修 → 出兵争点 → 信号集火或轰炸 → 总部攻防”。首版默认两套决策算法自主对战，支持观战与回放导出，不需要观看者指挥。

基线为双人、六轮、17×11 地图、三兵种和三种建筑。直接显示地图、血条、攻击范围、占点进度、轰炸预警与资源变化。使用类似基地攻防游戏的低多边形 3D 场景、独立兵种模型、阴影及行为标签。

## 2. 技术选型与目录

推荐 Python 3.11+ 无界面核心，FastAPI 提供本地 HTTP 接口，原生 HTML/CSS/JavaScript + Three.js 3D 渲染。前端暂不引入构建工具。核心采用整数 tick、HP、资源，节点时间存整数 tick，展示时转换为秒。

以下为计划新增的结构，尚未全部存在：

```text
configs/balance-v0.2.json      # 数值唯一来源
src/thuai10/core/             # 状态、动作、路径、战斗、节点、终局
src/thuai10/bots/             # 脚本和随机合法策略
src/thuai10/server/           # 创建对局、step、导出回放
src/thuai10/env/              # 双代理环境、观测编码和动作掩码
web/                         # 单页演示界面
tests/                       # 结算、回放和接口测试
scripts/                     # 批量对战与统计
docs/                        # 规则、来源、计划与运行说明
```

借鉴 [THUAI9](https://github.com/eesast/THUAI9#readme) 的逻辑、接口、界面、回放职责分离，不直接复制其通信或安装器。未来正式比赛可替换外层接口而复用规则核心。

## 3. 同一逻辑驱动演示与训练

核心只接受双方动作并推进状态。浏览器观战、脚本和 RL 包装器都调用同一入口，前端不另算伤害或胜负。

- `reset(seed, config)`：初始状态、双方观测及动作掩码。
- `step(actions_by_player)`：同时提交双方 0..71 动作，推进到下一决策边界或提前终局。
- `snapshot()`：完整裁判状态，供全信息 demo 和调试显示。
- 回放保存规则/schema版本、配置、seed、双方动作序列和关键状态校验值。

前端按 core 返回的 tick 状态做插值；暂停、倍速只控制何时调用 step。每方算法只读取旧观测并各调用一次，然后统一结算双方动作。1×每秒播放 2 tick，观众可暂停分析；界面分别显示模拟时间和播放速度。

## 4. 界面与交互

上方显示轮次、阶段、剩余时间、双方总部 HP、资源、科技、节点控制时长和当前超时分数。主画面显示镜像基地、建筑槽、三路部署点和两节点。

阶段操作由算法完成，侧栏只解释决策：

- 构建：建筑/科技/生产按钮，显示成本、批量和剩余资源/人口。
- 布局：点建筑再点目标槽，提示移动或交换。
- 维修：点建筑查看修复量和 20 资源成本。
- 进攻：选兵种与路线部署，从九宫区域选信号或轰炸；显示预备队、本轮次数和倒计时。

算法可选择 WAIT；观众控制仅包含重开、暂停、单步、1×/2×/4×、相机复位与回放导出。用不同形状区分兵种，选中实体显示属性与射程。事件栏只列出兵、节点易主、轰炸、建筑摧毁及胜负。教程每阶段一句，结算屏说明总部摧毁或超时评分各项。首版用按钮和格子点击，不要求拖拽。

## 5. 开发里程碑

| 阶段 | 实施内容 | 验收 |
| --- | --- | --- |
| M1 状态与阶段 | 配置、初始化、72 动作、掩码、四阶段、收入、运行说明 | 六轮 WAIT 恰好 360 tick、78 步；基础收入五次；非法动作不扣款，人口及建筑上限生效 |
| M2 战斗闭环 | BFS、冷却、同步伤害、护盾、节点、轰炸、撤军和胜负 | 能从开局到终局；无负资源或超上限；同动作回放完全一致 |
| M3 可玩演示 | 本地服务、3D 场景、观战交互、教程、观战、速度控制、回放 | 能完成一场；暂停/倍速不改结果；地图使用真实核心状态 |
| M4 训练与调参 | 固定观测、双方奖励、终止标志、批量运行及统计 | 至少 100 局随机合法对战全部结束；观测形状固定、掩码含 WAIT、终局奖励相反 |

M1 新增 README，记录实际安装、启动与测试命令；现在不把尚未实现的命令当成可运行命令。M2 重点测试：同 tick 双总部死亡判平、死亡单位完成已选攻击、最后一次轰炸在 tick 40 落下、死亡后不能占点、换边镜像一致、撤军保留单位 HP。用小场景验证具体数值，不能只看动画。

M3 实现抢点、防守、机器人推进、科技攻城四种脚本，预算不足时按预设优先级选择合法动作。完成一次算法自动对战，并解释抢点、换位、维修、信号和轰炸。

M4 先接随机合法代理，再考虑 PettingZoo Parallel API 适配，适配时核对官方版本接口。首版不要求 PPO、自博弈或选手 SDK。无界面基准记录每秒 tick 和整局耗时，注明机器环境，不先承诺吞吐指标。

## 6. 初始数值验证

四种脚本做六组两两对战并换边。固定规则与确定策略下重复 seed 不会产生新样本，需增加有种子的开局选择或探索策略，让至少 100 局覆盖不同动作轨迹。

统计胜负/平局、总部摧毁率、超时率、平均及 P95 模拟局长、节点易主次数、各兵种生产与死亡、资源花费构成。首轮希望多数对局落在 90–180 秒，至少三条路线有竞争力；这些是调参目标，尚未验证。

若一种策略通吃，先检查脚本能力差距，再分组调整总部/攻城、节点/收入、维修/防御参数。每次保存配置版本与结果。固定脚本集的胜率不能证明最优策略平衡。

## 7. 三分钟展示脚本

1. 打开页面即自动开始“抢点扩张 vs 科技攻城”，观看者不用操作部队。
2. 说明双方首轮投资：一方生产机器狗，另一方升级科技。
3. 进攻阶段观察分路出兵、节点驻守、机器人推进与射击连线。
4. 点击单位查看 HP、任务与目标；暂停和单步解释交火冷却、信号覆盖及轰炸。
5. 用 4×继续到第二轮，展示收入、维修与攻城车。
6. 完成对局，说明总部摧毁或超时分数如何决定胜负；换一组策略比较。

使用真实对局结果，不预设固定胜负。生产两个机器人等手工动作序列保留为核心预算测试，不作为演示主入口。

## 8. 交付与扩展

实现完成时交付启动说明、可玩界面、四种脚本、版本化配置、回放示例、测试结果和批量统计。当前已有可玩观战版，测试与新批量统计见 demo-review；浏览器回放导入、正式 SDK 和训练策略另行推进。

扩展顺序：调稳三兵种，再加入无人机或信息屏蔽弹，随后评估多阵营与败方领地占领。正式比赛服务器、Python/C++ SDK、打包分发和赛事运行单列工程计划。
