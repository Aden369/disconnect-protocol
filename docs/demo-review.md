## 2. 如何解释单位行为

- 机器狗部署到北/中路后守北节点，南路后守南节点；占完点会停下防守，站着不是程序卡住。
- 机器人与攻城车向敌方总部走；进入射程后停下作战，机器人优先敌军，攻城车优先建筑。
- “装填 / 等待攻击”表示目标在射程内但攻击冷却未结束。“移动冷却”表示该兵种尚未到下一次移动时间。
- “信号集结”表示算法主动临时覆盖默认目标；信号结束后恢复原任务，可能出现一次有意返回。算法决策栏和目标线会显示原因。
- 同格允许多个单位，3D 只做小幅队形错位以避免重叠；点击后显示真实逻辑格坐标，视觉偏移不参与战斗。
- 每轮结束统一撤回存活部队，保留剩余 HP；下一轮由策略重新部署。

## 3. 验证结果

- 原测试 66 项全部通过，但没有检测默认入口、脚本重复调用、生产槽和右方地图，所以不能据此宣布演示符合预期。
- 本次新增 11 项有意义的回归场景；共 **77 项测试通过**，包含跨进程 seed、一方一决策、生产可观测、镜像、任务稳定/信号覆盖、完整哈希和逐 tick 遥测。
- **12 场脚本对战**：六种组合各换边一次，6 场总部摧毁、6 场超时结算，无平局，平均模拟局长 132.9 秒；明细见 `results/review-bot-matchups-v0.2.json`。
- **100 场随机合法对战全部终止**：54/45/1（蓝胜/红胜/平），1 场总部摧毁、99 场超时；明细见 `results/review-random-games-v0.2.json`。随机对战只验证接口及结算稳定，不衡量策略质量。
- 原 `results/replay-example.json` 的 65 步 v0.1 回放仍验证成功，未静默破坏旧记录。
- 浏览器实际验证 3D 初始化、自动出兵、行为标签、算法决策、占点和交战、暂停/单步（12.5s→13.0s 后保持暂停）、点击单位显示真实格与目标，控制台无错误；截图见 `results/demo-3d-review.jpg`。Three.js 0.186.1 固定在 `web/vendor/`，不依赖在线 CDN。

## 4. 是否达到预期

| 目标 | 当前判断 |
| --- | --- |
| 短局、四阶段、初始兵种/建筑/经济 | 已实现；最多 180 秒模拟时间 |
| 算法互打，观看者无需指挥 | 已实现；四个脚本可选，默认抢点对攻城 |
| 类部落冲突的 3D 基地场景 | 已实现可旋转/缩放的低多边形立体场景；属于原型美术，未达到商业游戏素材精度 |
| 看懂单位在做什么、为何移动 | 由真实核心遥测解释，并展示目标、射击及冷却 |
| 方便接入强化学习 | 具备固定观测、72 动作和掩码、并行双方结算、无界面运行及终局奖励；尚未训练模型 |
| 正式比赛可用 | 仍需更多策略和种子评估、正式选手 SDK、比赛服务及分发；当前是演示原型 |
| 浏览器完整回放播放器 | 当前提供导出与命令行校验；浏览器导入/时间轴播放器仍是后续功能，不宣称已完成 |

脚本结果显示“抢点胜防守、推进胜抢点、防守胜推进”的初步策略差异；仅一个 seed 的换边结果不能证明规则已平衡。v0.1 的统计报告是历史基线，本次策略/行为变化后不能直接套用。
